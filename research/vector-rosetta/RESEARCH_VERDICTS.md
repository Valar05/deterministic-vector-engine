# Research Verdicts

## ADOPT

- Plain SVG paths, paint, affine transforms, clips, reusable symbols, and explicit DOM draw order.
- Spine JSON concepts for bone hierarchy, slots, skins, ordered constraints, timelines, events, and draw order—implemented independently from documented semantics.
- Hold, linear, and cubic-Bezier interpolation with seconds as the canonical clock.

## OBSERVE

- Inkscape editor namespaces and Live Path Effect recipes; retain as provenance while using rendered SVG paths.
- Harmony Raw Game Data XML and deformer exports until licensed, user-owned fixtures establish exact wire shapes.
- Lottie features outside the approved formal specification.
- SWF morph and display-list corner cases until bounded fixtures exist.

## NEEDS_KERNEL_EXTENSION

- IK constraints.
- Path constraints and constant-speed path traversal.
- Weighted path-control deformation.
- Animated topology changes.
- Nested clipping and blend modes beyond the strict SVG subset.

## REJECT

- Direct `.aep`, opaque Harmony scene, or opaque Spine project parsing.
- Copying or deriving from Spine runtime code without satisfying its license.
- ActionScript, arbitrary expressions, plugins, embedded video, and network references.
- Raster sprite sheets presented as vector ingestion.
- Guessed defaults for unknown formats, units, transforms, or feature semantics.

## Negative-knowledge receipts

- The local Thunder combined index contained no substantive Inkscape, Spine animation, Lottie, Toon Boom, After Effects, or SWF parser owner as of 2026-09-04.
- `.aep` is not the After Effects intake lane; documented Lottie/Bodymovin JSON is.
- Harmony's broadest deformers do not automatically survive Raw Game Data export; bake-required output is not a vector semantic mapping.
- SWF shape tags can be researched independently, but the container cannot be treated as safe data while executable tags remain enabled.
